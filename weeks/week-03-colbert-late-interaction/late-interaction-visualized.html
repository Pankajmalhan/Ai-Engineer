Week 3 — ColBERT companion

Inside Late Interaction

Three pictures for three mechanisms from concept.md: how a document turns into many vectors instead of one, how MaxSim actually scores a match, and what a "centroid" is when PLAID compresses the index. Same running example throughout — the query "who founded Studio Ghibli" against the real target document.

01 A document becomes many vectors, not one

A bi-encoder pools a whole passage into a single vector. ColBERT never pools — the passage is tokenized, and every token keeps its own 128-dimensional vector, produced by the same BERT encoder plus one small linear layer that projects its 768-dim output down to 128.

02 MaxSim: each query token shops for its own best match

Query tokens and document tokens are compared pairwise. For every query token, MaxSim looks at every token in the document and keeps only the single highest similarity — then adds those best-matches up. Nothing here is bounded like cosine similarity; it's a sum.

03 What a centroid actually is

Storing a full 128-number vector for every token in a whole corpus is expensive. PLAID's fix: pre-cluster all token vectors into a modest number of centroids, then store each token as just "which centroid is closest" plus a small correction — the residual.
